# Simple English & Clear Communication

## Core Rule
All communication, documentation, commit messages, code comments, and explanations must be written in **clear, simple, and plain English**.

---

## Guidelines

1. **Be Direct & Concise**
   - Use straightforward language.
   - Avoid filler words, fluff, unnecessary preamble, or corporate jargon.
   - Get straight to the point in 1-2 short sentences whenever possible.

2. **No Fancy Words**
   - Use "use" instead of "utilize".
   - Use "help" instead of "facilitate".
   - Use "start" instead of "commence".
   - Use "fix" or "solve" instead of "remediate".
   - Use "show" instead of "demonstrate".

3. **Short Sentences & Active Voice**
   - Keep sentences under 15-20 words.
   - Use active voice: *"The function validates the email"* instead of *"The email is validated by the function"*.

4. **Formatting for Readability**
   - Use bullet points, bold keywords, and concise lists instead of long blocks of text.
   - Code comments should explain **why** something was done in simple terms, not restate obvious syntax.

5. **Clarity Over Cleverness**
   - Write instructions so anyone on the team can understand them without ambiguity.
